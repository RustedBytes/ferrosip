# ferrosip.toml (phase 1 of the configuration redesign)

Design: "ferrosip Configuration & Routing Language" (two layers: a
declarative `ferrosip.toml` for **what runs**, and routing code for **how
messages are routed**). Phase 1 builds the first layer.

Routing stays in Kamailio-style `.cfg`; `.fsr` is phase 2. Existing
`.cfg`-only deployments keep working unchanged.

Status: implemented, including the gaps closed after the first release:
- **Schemas:** every module has one (`every_module_has_a_schema` test).
- **Implicit loading:** a module loads when the routing script calls its
  functions or uses its variables. With `--config` only; the index is
  `bin/ferrosip/src/functions.txt`, generated by
  `ferrosip schema --functions`.
- **Reload:** `cfg.reload` applies reloadable parameters and reports the
  rest.

Implementation:
- `bin/ferrosip/src/config.rs`: the loader.
- `crates/sip-core/src/schema.rs`: types and conversion.
- `Module::params()` in 20 modules.
- Tests: `tests/e2e_config.py`, plus unit tests that check every schema
  parameter against its module.

## What phase 1 delivers

```toml
[core]
workers = 8                      # UDP workers per socket
log_level = "info"
rpc_socket = "/run/ferrosip/rpc.sock"

[[listen]]
proto = "udp"
addr = "0.0.0.0:5060"
advertise = "${PUBLIC_IP}:5060"  # env interpolation

[[listen]]
proto = "tls"
addr = "0.0.0.0:5061"
tls = "default"

[tls.default]
cert = "/etc/ferrosip/cert.pem"
key = "/etc/ferrosip/key.pem"

[modules.txn]                    # = Kamailio tm
fr_timer = "30s"                 # durations are typed
fr_inv_timer = "120s"

[modules.location]               # = usrloc + registrar
db_mode = "write-back"           # enums are validated
max_expires = "1h"

[modules.media]                  # = rtpengine
enabled = "${feature.nat}"       # feature switch, no preprocessor
rtpengine_sock = ["udp:rtpengine:2223"]

[feature]
nat = true

[routing]
entry = "routes/main.cfg"        # relative to this file
```

```bash
ferrosip --config ferrosip.toml --overlay envs/prod.toml --set modules.txn.fr_timer=10s
ferrosip check --config ferrosip.toml --explain   # merged config, where each value came from
ferrosip schema [--markdown] [module]             # parameter reference from the schemas
```

### Parts

1. **Schemas in Rust, next to each module.** `Module::params()` returns
   `ParamSpec`s, each with:
   - a name and a type: string, int (with a range), bool, duration (with
     the unit the module expects), enum (with its values, which may map to
     Kamailio's numbers), or a list (one `modparam` per item);
   - a default, docs, and whether it is reloadable.

   Validation, `check --explain`, `ferrosip schema` and the generated
   `docs/modules-reference.md` all come from these. A module without a
   schema yet still loads: its keys pass straight to the module's own
   `set_param` checks, and `check --explain` marks them as not
   schema-checked.
   - Parameters marked reloadable (tm timers, registrar expiries, dialog
     timeouts, pike…) change on `cfg.reload`.
   - `cfg.reload` returns
     `{"applied": [...], "needs_restart": [...], "routes": …}`. Values
     that need a restart keep their running value until then.
2. **Module names.**
   - `[modules.x]` takes the ferrosip names. Each is a short noun for what
     the module does, and one name may cover several related Kamailio
     modules (when they share no function or parameter name):

     | ferrosip | Kamailio | ferrosip | Kamailio |
     |---|---|---|---|
     | `txn` | tm, tmx | `stateless` | sl |
     | `location` | usrloc, registrar | `auth` | auth, auth_db |
     | `sip` | siputils, sanity, maxfwd | `text` | textops, textopsx |
     | `vars` | pv, avpops | `utils` | cfgutils, corex, kex |
     | `log` | xlog | `ip` | ipops |
     | `stats` | statistics | `timers` | rtimer |
     | `route_set` | rr | `nat` | nathelper |
     | `balancer` | dispatcher | `acl` | permissions |
     | `domains` / `aliases` / `groups` | domain / alias_db / group | `carriers` | lcr |
     | `prefix_tree` / `prefix_routes` | mtree / prefix_route | `speed_dial` | speeddial |
     | `redirect` | uac_redirect | `client` | uac |
     | `shared_tables` | htable | `limits` | pike, ratelimit |
     | `pipe_limits` | pipelimit | `security_filter` | secfilter |
     | `blocklist` | blst, userblocklist | `dialog` | dialog, dlgs |
     | `media` | rtpengine | `cdr` | acc |
     | `credit` | cnxcc | `topology` | topoh |
     | `presence` | presence, presence_xml, presence_dialoginfo | `presence_client` | pua, pua_dialoginfo |
     | `resource_lists` | rls | `shared_lines` | sca |
     | `offline_messages` | msilo | `pending_calls` | tsilo |
     | `sql` | sqlops | `redis` | ndb_redis |
     | `http` | xhttp, http_async_client | `json_doc` | jansson |
     | `admin` | jsonrpcs | `trace` | siptrace |
     | `events` | evapi | `sip_dump` | sipdump |
     | `lua` | app_lua | `diameter` | cdp, cdp_avp |

     The others keep their name (`path`, `outbound`, `enum`, `exec`,
     `dialplan`, `json`, `http_client`, `keepalive`, `async`, `ims_*`,
     `webui`, `ai`, `prometheus`, …). `.fsr` namespaces are the same names.
   - Kamailio names work too in `ferrosip.toml` (`[modules.tm]`), and in a
     `.cfg` (`loadmodule "tm"`). A member of a group that has no parameter
     set loads by its own name (`[modules.presence_xml]`), or when the
     routing uses one of its functions.
   - A key goes to whichever member module declares it; an unknown key is
     an error that lists the valid ones, with a "did you mean".
3. **Implicit loading and order.**
   - A module loads when it has a `[modules.x]` section (`enabled = false`
     skips it), when the routing `.cfg` loads it, or when the script uses
     one of its functions or variables (`sl_send_reply` → sl, `$sht` →
     htable). The routing file needs no `loadmodule` lines.
   - A plain `.cfg` without `--config` keeps Kamailio's rule:
     `loadmodule` is required.
   - The load order comes from declared dependencies (`dialog` after
     `txn`, `registrar` after `usrloc`), not from file order.
4. **Values.**
   - `${ENV}` and `${ENV:-default}`.
   - `${feature.x}` reads the `[feature]` table, and a value that is
     exactly one `${…}` keeps its type (bool, int).
   - Durations like `"500ms"`, `"30s"`, `"2m"`, `"1h"`, `"1d"`, or a bare
     number in the module's unit.
   - Booleans become 0/1 for Kamailio-style parameters.
5. **Layers, in order:**
   1. the base file;
   2. each `--overlay` (deep merge: tables merge, other values and arrays
      replace);
   3. each `--set dotted.path=value` (a TOML value, else a string).

   `check --explain` prints every effective value with its source
   (`ferrosip.toml`, `envs/prod.toml`, `--set`, `default`).
6. **Core and transports.** `[core]` covers:
   - workers, log level and the RPC socket;
   - shutdown timeout and advertise address;
   - TCP limits and timeouts, and WebSocket origins and deflate.

   `[[listen]]` takes `proto`, `addr`, optional `advertise` and `tls`.
   `[tls.<name>]` takes `cert`, `key`, `ca`, `verify_client` and `sni`:
   - `default` is the global certificate;
   - other names are per-listener profiles.

   `[tls.default] profile` reads a Kamailio `tls.cfg` (per-listener and
   per-peer profiles).

   Command-line flags still win over the file.
7. **Kamailio leftovers** (what `ferrosip import` writes,
   [import.md](import.md)):
   - `[modules.x.kamailio] param = value` passes values to the module
     exactly as `modparam("x", "param", value)` would. They are not
     checked against the schema, so this is for parameters the schema
     doesn't list.
   - `[cfg_vars.group] name = value`, or
     `name = { value = …, desc = "…" }`: Kamailio custom config variables,
     read with `$sel(cfg_get.group.name)` and changed with
     `cfg.set_now_*`.
8. **Mixing with `.cfg`.**
   - The entry `.cfg` may still contain `loadmodule`, `modparam` and core
     parameters.
   - A parameter set in both places is an error that names both
     locations: one source of truth.
   - `-f file.cfg` alone works as before.

### Not in phase 1

- `.fsr` routing, `await`, events and `ferrosip test` (phase 2+).
- `ferrosip fmt` for TOML, and the language server.
- Reloading listeners, TLS, core settings and modules. `cfg.reload`
  reports them as needing a restart.
- The `ferrosip import kamailio.cfg` transpiler (after `.fsr`).
- Merged APIs (`location.save` as one module) and storage backends picked
  in TOML. The names map onto the existing modules for now.
